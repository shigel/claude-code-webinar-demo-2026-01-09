# Skills の有無による出力比較分析

## 概要

main ブランチ（skills なし）と step1-skills ブランチ（skills あり）で、それぞれ3回ずつ PR レビューを実行し、出力の違いを分析した。

---

## 1. セクション構成の比較

### main ブランチ（skills なし）: セクション名がバラバラ

| 実行 | セクション構成 |
|------|---------------|
| 1回目 | レビュー概要 → 必須修正事項 → リスク・懸念事項 → 保守性 → テスト → 提案事項 → 検証計画 → 総評 |
| 2回目 | 要約 → Must-fix → リスク/Edge Cases → 保守性 → テスト → 提案事項 → 総評 |
| 3回目 | 概要 → プロジェクト構成 → 発見事項 → 推奨事項 → 総評 |

**観察:**
- セクション数が 5〜8 で変動
- セクション名が統一されていない（「必須修正事項」vs「Must-fix」vs「発見事項」）
- 「検証計画」など、毎回出るわけではない独自セクションがある

### step1-skills ブランチ（skills あり）: 6セクション固定

| 実行 | セクション構成 |
|------|---------------|
| 1回目 | 要約 → Must-fix → リスク/edge cases → 保守性 → テスト → 提案事項 |
| 2回目 | 要約 → Must-fix → リスク/edge cases → 保守性 → テスト → 提案事項 |
| 3回目 | 要約 → Must-fix → リスク/edge cases → 保守性 → テスト → 提案事項 |

**観察:**
- **完全に一致**（6セクション固定）
- SKILL.md で定義した通りの構成
- 3回目は一部英語が混じったが、セクション構成は維持

---

## 2. 対話の違い

### main ブランチ: 質問が発生することがある

```
2回目のログ:
⏺ User answered Claude's questions:
  ⎿  · step1-skills ブランチで何をレビューしますか？ → 現在のmainブランチすべて

3回目のログ:
⏺ User answered Claude's questions:
  ⎿  · どのブランチをレビューしますか？ → main（最近のコミット）
  ⎿  · 何個の最近のコミットをレビューしますか？ → 全体の状態
```

**問題点:**
- 曖昧な指示に対して Claude が質問を返す
- ユーザーの回答が必要になり、自動化が困難

### step1-skills ブランチ: 質問なしで即座に実行

```
全3回のログ:
⏺ PR レビューを開始します。現在のブランチとステージング済みの変更を確認します。
（質問なしで即座にレビュー開始）
```

**利点:**
- スキルが「何をすべきか」を明確に定義しているため、質問が発生しない
- 自動化・CI/CD への組み込みが容易

---

## 3. スキル起動の明示

### main ブランチ: スキル表示なし

```
> このブランチをPRレビューして
⏺ 現在のブランチの状態を確認して、PRレビューを行います。
```

### step1-skills ブランチ: スキル起動が明示される

```
> The "pr-review" skill is running
⏺ PR レビューを開始します。
```

**利点:**
- 「どのスキルが動いているか」が明確
- デバッグや期待値の確認が容易

---

## 4. 出力品質の一貫性

### main ブランチ: 品質にばらつき

| 実行 | 特徴 |
|------|------|
| 1回目 | 非常に詳細（172行）、検証計画まで含む |
| 2回目 | 中程度（284行）、対話で追加情報を取得 |
| 3回目 | 簡潔（192行）、対話で範囲を確認 |

### step1-skills ブランチ: 品質が安定

| 実行 | 特徴 |
|------|------|
| 1回目 | 135行、6セクション完備 |
| 2回目 | 112行、6セクション完備 |
| 3回目 | 88行、6セクション完備（一部英語混在） |

**観察:**
- skills ありの方が出力長が安定
- 構成が固定されているため、読み手が情報を探しやすい

---

## 5. 結論

| 観点 | main (skills なし) | step1-skills (skills あり) |
|------|-------------------|---------------------------|
| セクション構成 | 毎回異なる（5〜8セクション） | 固定（6セクション） |
| セクション名 | バラバラ | 統一 |
| 対話の発生 | あり（質問が発生） | なし（即座に実行） |
| スキル起動表示 | なし | あり |
| 出力長 | 88〜284行（ばらつき大） | 88〜135行（安定） |
| 自動化適性 | 低（対話が必要な場合あり） | 高（対話不要） |

---

## 6. skills の価値

1. **出力の標準化**: レビュー観点とセクション構成を固定できる
2. **対話の削減**: 曖昧さを排除し、即座に実行
3. **チーム間の一貫性**: 誰が実行しても同じ形式で出力
4. **期待値の明確化**: 何がどの順番で出力されるか予測可能
5. **自動化対応**: CI/CD や定期実行に組み込みやすい

---

## 7. 注意点

1. **3回目のログで一部英語混在**: 「必ず日本語で出力すること」と指定していても、100% 遵守されるとは限らない
2. **allowed-tools の制約**: `Read, Grep, Glob` のみ許可しているため、`git diff` などは Bash 経由で実行できない（呼び出し元で事前取得が必要）
3. **Skills のロードタイミング**: ブランチ切り替え後は Claude Code の再起動が必要
